# Automatización de Documentación Técnica con Gemini CLI y GitHub Actions

## Resumen
Se ha integrado un nuevo flujo de trabajo de GitHub Actions para automatizar el proceso de generación de documentación técnica dentro de la carpeta `docs/`. Este workflow se dispara exclusivamente cuando se realiza un merge desde la rama `develop` hacia `main`, empleando Gemini CLI para analizar inteligentemente los commits y diferencias introducidas para redactar un reporte técnico estructurado y actualizar un índice consolidado.

## Detalle técnico

### Canalizaciones de Integración Continua (CI/CD)

#### `.github/workflows/generate-docs.yml`
Se introduce este nuevo workflow para gestionar la generación asíncrona de documentación del repositorio. Sus especificaciones técnicas clave incluyen:
* **Filtros de Activación (Triggers):** Se ejecuta únicamente al cerrarse un Pull Request (`pull_request: closed`) con destino a `main`. Adicionalmente, cuenta con una condición de control que requiere que el PR haya sido efectivamente fusionado (`merged == true`) y que la rama origen sea estrictamente `develop`.
* **Permisos del Entorno:** Requiere permisos de escritura de contenido (`contents: write`) para habilitar la capacidad de realizar commits automáticos sobre la rama `main` en tiempo de ejecución.
* **Extracción de Cambios:** En la etapa inicial, realiza un checkout completo del repositorio (`fetch-depth: 0`) para calcular las diferencias entre el SHA base (`base.sha`) y el SHA resultante de la fusión (`merge_commit_sha`). El diff extraído excluye intencionalmente la propia carpeta de documentación (`docs/**`) y los archivos de bloqueo (`lockfiles`) para optimizar el contexto de envío.
* **Integración con Gemini CLI:** Usa la acción `google-github-actions/run-gemini-cli@v0.1.22`. Incorpora la variable de entorno `GEMINI_CLI_TRUST_WORKSPACE: "true"` para evadir las alertas de directorios no confiables del runner y deshabilita el uso de herramientas del core mediante JSON settings para forzar una ejecución segura de solo lectura de contexto.
* **Persistencia y Control de Versiones:**
  * Almacena cada documento bajo un esquema de rutas temporal: `docs/YYYY-MM-DD/HH-MM-SS_pr-<PR_NUMBER>.md`.
  * Genera o actualiza de forma automática el índice consolidado `docs/README.md`, insertando una tabla con referencias relativas a la fecha, hora y número de PR correspondiente.
  * Realiza el commit y push de vuelta a la rama `main` utilizando el usuario configurado `poketeams-docs-bot` y añadiendo el tag `[skip ci]` para prevenir bucles recursivos en el workflow.

## Cambios de API o dependencias
* **Dependencias de CI:** Se añade el uso de la acción de GitHub `google-github-actions/run-gemini-cli@v0.1.22` con dependencia del secreto de repositorio `GEMINI_API_KEY`.
* No se reportan cambios en el esquema de GraphQL ni en endpoints REST de los controladores de Java.
